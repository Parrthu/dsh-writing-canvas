# 开发环境能力（供 AI 与自己复用）

这份文档记录本机上**可用于自我验证**的能力，以及踩过的坑。
目的是：以后（包括 AI 自己）不必重新摸索，直接照做即可。

## 一、我能"看见"界面

### 截图

```bash
screencapture -x /tmp/shot.png      # -x 关闭快门声
```

- 需要 **系统设置 → 隐私与安全性 → 屏幕录制** 授权给宿主进程；未授权时报
  `could not create image from display`。
- 权限**授予后立即生效**，不必重启 App（实测）。

### 坐标换算（关键，容易踩坑）

Retina 屏上截图像素是逻辑坐标的 **2 倍**：

| 量 | 值示例 |
|---|---|
| 截图像素 | 2940 × 1912 |
| 逻辑坐标（AppleScript 用） | 1470 × 956 |
| 换算 | `逻辑 = 截图 / 2` |

**AppleScript 的点击用逻辑坐标**，直接拿截图像素去点会点到两倍远的地方。

### 放大细节

用内置 Python + Pillow 裁剪放大，比看整屏清楚得多：

```python
from PIL import Image
im = Image.open('/tmp/shot.png')
crop = im.crop((1600, 200, 2900, 430))            # 截图像素坐标
crop.resize((int(crop.width * 1.6), int(crop.height * 1.6)), Image.LANCZOS).save('/tmp/crop.png')
```

## 二、我能"操作"界面

需要 **系统设置 → 隐私与安全性 → 辅助功能** 授权。

```bash
# 前台应用名（只读，用于确认权限是否可用）
osascript -e 'tell application "System Events" to get name of first application process whose frontmost is true'

# 激活应用
osascript -e 'tell application "DeepSeek Harness" to activate'

# 在逻辑坐标 (x, y) 点击
osascript -e 'tell application "System Events" to click at {x, y}'

# 按键 / 组合键
osascript -e 'tell application "System Events" to keystroke "a" using command down'
osascript -e 'tell application "System Events" to key code 123 using shift down'   # ⇧← 选中
```

常用 key code：`123`← `124`→ `125`↓ `126`↑ `48`Tab `36`Return `53`Esc `51`Delete

### 可靠的交互自检套路

1. `screencapture` 截图 → 看当前状态
2. 用逻辑坐标点击目标控件
3. 用键盘制造状态（例如 `⇧←` 选中文字）
4. 再截图 → 确认界面出现了预期变化

## 三、界面自检通道（不依赖截图）

客户端会把自己的 DOM 结构上报给宿主，随时可读：

```bash
curl -s http://127.0.0.1:19387/writing-canvas/api/client-report
```

自检字段包括：`toolbarButtons`、`typeSelect`、`specOptions`、`exportButton`、
`drawer` / `drawerOpen`、`hiddenColumns`、`annotationCards`、`highlightMarks`、
`versionRows`、`editorChars`、`editorHeight` / `rootHeight`、`writingPill` 等。

**为什么需要它**：客户端跑在浏览器里，宿主看不见。截图能看"长什么样"，
自检能看"结构对不对"，两者互补。

## 四、宿主开发回路（HMR）

`~/.dsh/profiles/desktop/cordis.patch.yml` 里为写作插件目录开了模块监听，因此：

| 改动 | 生效方式 |
|---|---|
| `src/*.js`（宿主） | 保存即热重载，无需重启 |
| `client/client.js`（浏览器） | 保存即热重载，页面无需刷新 |
| 新增插件行 / 新增包子路径导出 | **需要重启 App**（宿主启动时缓存包元数据） |
| `cordis.patch.yml` 本身的行结构变化 | 需要变更 profile 的 bundles 列表触发重新组合 |

## 五、已知的坑（都踩过）

1. **浏览器 EventSource 拿到 404 会永久放弃重连**。宿主每次热重载都会短暂摘掉
   `/events` 路由，所以客户端**必须自己实现重连**，否则实时能力会静默失效。
2. **热重载会重建宿主的内存状态**（事件总线、诊断上报缓冲），排查时留意时间戳。
3. **窄栏里不要把多个面板排成列**：单列网格会让它们竖直堆叠，把正文压到看不见。
   窄栏应该只给正文，其余收进默认收起的抽屉。
4. **空白内容绝不能静默覆盖非空文档**——已有硬防护，需要 `allowEmpty: true` 才放行。

## 六、渲染出问题时的定位方法（血泪教训）

### 症状：槽位标签在，内容一片空白，且**没有任何错误上报**

原因：槽位系统有**监督通道**，组件渲染抛出的异常会被它接住，
**不会冒泡到 `window.onerror`**。所以表面看起来风平浪静，实际渲染早已中断。

### 定位三步

**第一步：装全局错误上报**（本插件已内置，见 `client.js` 的 `apply`）：

```js
window.addEventListener('error', (e) => report('client:error', { message: e.message, line: e.lineno }));
window.addEventListener('unhandledrejection', (e) => report('client:rejection', { reason: String(e.reason) }));
```

**第二步：渲染探针**。在 JSX 的 children 里插入**逗号表达式**，不会影响渲染，
却能精确定位到哪一段抛出：

```js
return h('div', { className: 'root' },
  (report('diag:r0', {}), null),
  h(Header, ...),
  (report('diag:r1', {}), null),
  h(Body, ...),          // ← 如果 r1 命中而 r2 没命中，问题就在 Body
  (report('diag:r2', {}), null),
);
```

**第三步：effect 探针**。如果连 `useEffect` 都没执行（说明 React 根本没提交），
在 effect 开头再插一个上报即可确认。

### 另一类坑：脚本改动**静默失效**

用 `str.replace(old, new)` 改代码时，**锚点不匹配不会报错，只会什么都不做**，
而脚本仍会打印"已完成"。本项目就被这个坑过一次：图标组件没插进去，
`iconButton` 未定义 → 整个画布白屏。

**规矩**：脚本改代码后，必须再用 `grep` 或 `node --check` 验证结果，
不能相信"已完成"三个字。

### 临时诊断的手段与代价

诊断探针会迅速灌满 `/client-report` 的 50 条环形缓冲，**把真实上报挤出去**，
反而看不清真相。定位完必须**立刻清理探针**。
